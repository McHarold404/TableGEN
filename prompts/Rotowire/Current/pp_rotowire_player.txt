1. A new table that uses the target schema columns and rows.
2. A list of extra columns and/or extra rows that appeared in the original table but do not appear in the target schema.
3. A list of missing columns and/or missing rows that appear in the target schema but not in the original table.

Follow these steps carefully, reasoning step by step:

1. Map columns:  
   - For each column in the target schema, see if a corresponding column (or parseable combination of columns) exists in the original table.

2. Map rows:  
   - The target schema specifies certain row headers (e.g., players’ names). For each target row header, find its counterpart in the original table’s row if possible (taking note of minor spelling differences if needed).  
   - If a row in the target schema does not appear in the original data, treat it as a missing row.  
   - If a row in the original table does not appear in the target schema, treat it as an extra row.

3. Extra columns:  
   - If you find columns in the original table that do not exist in the target schema (e.g., “Team,” “Player”), list them separately under “Extra Columns.”

4. Missing columns:  
   - If you find columns in the target schema that cannot be filled from the original (or a parsed version of the original), list them separately under “Missing Columns.”

5. **Output**: Produce three separate outputs in the final answer:  
   - Transformed Table (formatted with the target schema’s row and column headers, and with original values parsed into the correct spots). If any value is missing (like “None” in the original), keep it as blank or “None” in the transformed table.  
   - Extra Columns/Rows  
   - Missing Columns/Rows
